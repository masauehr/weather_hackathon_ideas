# ID-05 気象病アシスタント

**[← README（目次）](../../README.md)** ・ [候補一覧](README.md) ・ 他候補: [c32 天気図VLM](c32_weather_chart_vlm.md) / [c17 ビーチ日和](c17_beach_day_planner.md) ・ 参照: [idea_catalog ID-05](../idea_catalog.md) ・ [correlation_studies CS-03 / CS-10](../correlation_studies.md) ・ [genai_angles GA-04](../genai_angles.md)

## 一言
気圧の急降下・気温差・湿度から「気象病リスク指数」を時系列予測し、生成AIがリスクの理由説明とセルフケア助言、服薬タイミングの相談に対話で応じる。プロフィール（片頭痛・メニエール・関節痛など）で個別化する。

> **重要**: 医療機器でも診断でもない。一般的な生活情報の提供にとどめ、症状が続く/強い場合は受診を促す固定文言を常に添える。個人の体調ログは端末内保存を基本とし、外部送信しない設計を明記する。

## 課題 / 誰のため
- 「天気が悪いと頭が痛い/めまいがする」人は多いが、いつ・なぜ・どう備えるかの手がかりが乏しい。
- ターゲット: 片頭痛・緊張型頭痛・メニエール病・古傷/関節痛・気分の落ち込みを気圧変化で感じる人。

## 提供する体験
1. **今日〜72時間のリスク指数**: 3時間刻みで「低/中/高」。「明日15時ごろ、6時間で8hPa下降。あなたの記録では高リスク帯」。
2. **理由の説明**: 「効いている要因: 24時間気圧変化 -9hPa、気温差 7℃。あなたは"急な下降"に反応しやすい傾向（過去12件中9件で頭痛）」。
3. **先回りのセルフケア助言**: 「前日は睡眠を確保、カフェインは控えめ、頓服があるなら早めの服用を主治医と相談。明日は予定を詰めすぎない」。
4. **相談チャット**: 「明日の朝と昼、どっちに頓服を飲むべき?」等に、一般的な考え方＋"主治医に確認を"で応答。
5. **記録と振り返り**: 頭痛の有無・強さ・対処を記録 → 週次で「今週は気圧変動が大きく、火・木がつらかった。予兆の◯時間前対処が効いた回が多い」。

## リスク指数の設計
- **特徴量**: 気圧の複数窓変化（6h / 12h / 24h の差分と変化率）、気圧の絶対水準、気温差（日較差・前日差）、湿度、天候急変フラグ（前線通過）、時間帯、曜日。
- **個人化**: 記録が貯まる前は「一般的な感受性モデル」（先行研究ベースの重み）。記録が貯まったら個人内でロジスティック回帰を再学習し、「効く窓」を個人ごとに特定（[CS-10](../correlation_studies.md)）。
- **出力**: 発生確率 → 3段階に量子化。確率とキャリブレーション（Brier）も内部で持つ。
- **ベースライン**: 「気圧が下がる日は高リスク」という単純ルール。個人モデルがこれを上回るか常に比較。

## データ（入力）
| データ | 取得元 | 備考 |
|---|---|---|
| 海面気圧・気温・湿度（実況＋予報） | Open-Meteo | 地点・1時間・登録不要。過去も取れる |
| 前線・天気急変 | 気象庁 予報テキスト / 天気図 | 急変フラグの補助 |
| 個人の体調ログ | アプリ内入力（端末内保存） | 頭痛有無・強さ(0–3)・時刻・対処・効果 |
| （集団検証用）"頭痛"言及量 | Googleトレンド or Bluesky検索 | 個人データなしでモデルの当たりを見る（[CS-03](../correlation_studies.md)） |
| プロフィール | 疾患カテゴリ、既知の誘因、頓服の有無（薬名は保存しない） | 個別化の入力 |

## MLパート
- 個人内ロジスティック回帰（説明性重視）。特徴量重要度をそのまま説明文に使う。
- 集団レベルはポアソン/ロジスティックで "頭痛言及量 ~ 気圧変化" を回帰し、一般モデルの初期重みを較正。
- 因果の注意: 「天気が悪い→外出減・活動変化」が交絡。可能な範囲で活動量を共変量に。断定的な因果主張はしない。

## 生成AIパート
- **入力**: リスク指数の時系列＋効いている特徴量（値と寄与）＋プロフィール＋直近の体調ログ要約。
- **出力**:
  - リスク説明（数値を引用、「あなたの記録では」を根拠付きで）
  - 時間軸のセルフケア（前日/当日朝/悪化前）
  - チャット応答（一般論＋受診/主治医相談の促し）
  - 週次振り返りレポート
- **ガードレール（最重要）**:
  - 診断・処方・薬の増減の指示をしない。「主治医・薬剤師に相談」を必須で添える。
  - 数値（hPa、℃、確率、過去件数）は必ずモデル/ログ由来の値を引用。LLMに推定させない。
  - 症状が「強い/長引く/いつもと違う/しびれや麻痺を伴う」等はレッドフラグとして受診を強く促す固定分岐。
  - 不確実性を明示（「記録が少ないため精度は限定的」）。
  - 体調ログ・プロフィールは端末内保存が既定。クラウドLLMに渡す際は最小限（要約・数値のみ、薬名や自由記述の個人情報は送らない）。
  - プラセボ/ノセボへの配慮: 「必ずつらくなる」と断定せず可能性として提示。

## アーキテクチャ
```
[Open-Meteo 気圧/気温/湿度] --> [特徴量: 多窓変化・日較差・急変フラグ]
[個人の体調ログ(端末内)] ------> [個人モデル(ロジスティック) or 一般モデル]
                                        |
                     リスク時系列 + 寄与度 + プロフィール要約
                                        |
                          [LLM: 説明 / セルフケア / チャット]  <- 固定ガードレール文
                                        |
              [UI: リスク帯グラフ + 説明 + ケア + 記録フォーム + 週次レポート]
```
- 記録はローカルストレージ or SQLite。クラウド送信は数値サマリのみ。

## MVPスコープ（48h）
- [ ] Open-Meteo から指定地点の気圧・気温・湿度（過去30日＋予報72h）
- [ ] 特徴量: 6/12/24h 気圧変化、日較差、急変フラグ
- [ ] 一般感受性モデル（先行研究ベースの固定重み）でリスク3段階
- [ ] 体調ログの手入力フォーム（端末内保存）＋ 5件以上でミニ個人回帰
- [ ] LLM: 「明日のリスクと理由＋セルフケア」＋受診促し固定文
- [ ] UI1画面: 72hリスク帯グラフ、説明カード、記録ボタン

### ストレッチ
- 「効く窓」の個人特定と可視化、週次振り返りレポート、通知（悪化◯時間前）、家族共有、ウェアラブル（睡眠・活動量）連携、方言/やさしい日本語。

## 3分デモ筋書き
1. （共感）「天気で頭が痛くなる人?」— 手が挙がる。
2. （予測）アプリが「明日15時、6時間で8hPa下降。高リスク」と示す。帯グラフで一目。
3. （理由）「あなたの記録では"急な下降"の翌日に9/12回、頭痛」。根拠が数字で出る。
4. （備え）「前日は睡眠確保、頓服は主治医と相談して早め、予定を詰めない」。
5. （対話）「朝と昼どっち?」に一般論＋"主治医に確認を"で丁寧に答える。
6. （締め）「つらくなる前に、備える。医療の代わりではなく、生活の味方として」。

## リスクと対策
| リスク | 対策 |
|---|---|
| 医療アドバイスと受け取られ、誤った自己判断を招く | 診断/処方をしない、全出力に受診・主治医相談の固定文、レッドフラグ分岐、免責をUI常設 |
| 「効く」の根拠が弱い（個人データ不足・プラセボ） | 一般モデルで開始しデータ蓄積で個人化、精度の限界を明示、断定を避ける |
| 個人の健康情報の取り扱い | 端末内保存を既定、クラウドへは数値サマリのみ、薬名・自由記述は送信しない旨を明記 |
| 交絡（悪天候→行動変化）で相関を過大評価 | 活動量を共変量に、因果主張を避け「関連」と表現 |
| デモが会話中心で視覚的に地味 | リスク帯グラフ・寄与度バー・週次レポートで視覚要素を確保 |

## ID-31（自然言語フロント）との統合
- 「今週、頭痛に気をつける日は?」→ リスク時系列を評価して回答。
- 「なんで明日がつらいの?」→ 寄与度の言語化。
- チャットにリスク帯グラフを差し込む。
