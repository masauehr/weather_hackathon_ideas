# ID-17 ビーチ日和スコア＋観光プラン生成

**[← README（目次）](../../README.md)** ・ [候補一覧](README.md) ・ 他候補: [c32 天気図VLM](c32_weather_chart_vlm.md) / [c05 気象病](c05_meteoropathy_assistant.md) ・ 参照: [idea_catalog ID-17](../idea_catalog.md) ・ [correlation_studies CS-05](../correlation_studies.md) ・ [existing_assets](../existing_assets.md)

## 一言
天気・気温・風・波高・潮位・UVから「海日和スコア」を算出し、時間帯別のベストタイムと、潮見表に沿った半日プランを生成AIが提案する。沖縄の海をターゲットにする。

## 課題 / 誰のため
- 「海に行きたいが、いつ行けば快適か（潮・波・風・日差し）」の判断は情報が散らばっていて難しい。
- ターゲット: 沖縄への観光客、家族連れ、シュノーケル/磯遊び/SUP をする人、宿・アクティビティ事業者。

## 提供する体験
1. **スポット×日時を選ぶ** → 海日和スコア（0–100）と内訳（快適さ / 安全 / 遊びやすさ）。
2. **72時間タイムライン**: 3時間刻みでスコアを帯グラフ表示。「明日10:30–13:00が引き潮＆微風でベスト」。
3. **半日プラン生成**: 「10:30着で干潮の磯観察、12:00に日差しピークなので日陰休憩、13:30から満ち始めるので浅瀬で泳ぐ。日焼け止めSPF50、ラッシュガード推奨」。
4. **注意喚起**: 高波・離岸流・雷・UV過多・熱中症を警告。遊泳可否の目安。
5. **代替提案**: スコアが低い日は「午前の別スポット」「翌日」「海以外（ガンガラーの谷等）」を提示。

## スコア設計（海日和スコア）
| 要素 | 指標 | 効き方 |
|---|---|---|
| 天気 | 降水確率・雲量・雷可能性 | 雨/雷で大幅減点 |
| 気温・体感 | 気温・湿度・WBGT | 高すぎ（熱中症）も減点 |
| 風 | 平均風速・突風 | 弱いほど良い、5m/s超で減点、10m/s超で不可 |
| 波 | 有義波高・周期・うねり向き | 磯遊び/シュノーケルは低波高が良い、SUPは中程度可 |
| 潮位 | 干満・時刻 | 遊び方で最適が変わる（磯=干潮寄り、遊泳=中〜満潮） |
| 日差し | UVインデックス・日照時間 | 適度が良い、UV8以上は対策必須の注記 |
| 透明度代理 | 直近降雨（河川からの濁り）・うねり | 大雨後は減点 |

- **用途別プロファイル**: `snorkel` / `tidepool`（磯遊び） / `swim` / `sup` / `sunset` で重みを切替。
- スコアは重み付き線形＋不可条件（雷・高波・強風）でのゲート。**まずルールベースで作り、実測の「体感良かった」ログが集まれば回帰に差し替え**（[CS-05](../correlation_studies.md) の枠組み）。

## データ（入力）
> 気象はすべて気象庁。過去1年の検証は obsdl、当日運用は bosai。GRIB（GPV）は使わない。

| データ | 取得元 | 備考 |
|---|---|---|
| 天気・気温・風・降水・日照 | 気象庁 obsdl（過去検証）／気象庁 bosai forecast・amedas（当日運用） | 沖縄の代表地点（那覇・久米島・南大東 等） |
| UV（紫外線） | 気象庁 紫外線情報（分布図・地点予測） | 数値の時系列が取りにくい場合は日射量で代替 |
| 波高・周期・うねり | 気象庁 沿岸波浪・ナウファス（全国港湾海洋波浪情報網）等の**公開値**を確認 | GPV（GRIB）は不可。1年分そろわなければ「波」項目を外す |
| 潮位（実測・天文・時刻） | 気象庁 bosai tide（`tide_viewer` は取得コードの参考） | 沖縄7観測所。tide_obsは29日分＝96点スライス注意 |
| 潮見表（干潮・満潮時刻） | 気象庁 tide_astro / tide_time | プラン生成の骨 |
| スポット座標・特徴 | 自作の小さなJSON（10–20スポット） | 名前・座標・タイプ・最寄り観測所・注意点。公開情報のみ |
| 熱中症の目安 | 気象庁 obsdl の気温・湿度・日射から WBGT 近似計算（または環境省WBGT） | 夏の警告 |

## MLパート
- MVPはルールベーススコア（ML不要）。
- ストレッチ: 「行ってよかった度」の投稿/評価を集めてスコア係数を回帰学習。用途別に係数を分ける。
- 透明度予測（大雨後の濁り回復）を降雨履歴から簡易回帰。

## 生成AIパート
- **入力**: スコア内訳（JSON）＋ 潮見表（時刻・潮位）＋ 用途プロファイル＋ ユーザー条件（人数、子どもの有無、滞在可能時間、車/徒歩、カレンダー予定があれば）。
- **出力**: 時系列の半日プラン（到着時刻・各アクティビティ・休憩・持ち物・撤収時刻）＋ 一言サマリ＋ 警告。
- **ガードレール**:
  - 時刻・潮位・風速・UV値は必ず入力JSONから引用。LLMに数値を作らせない。
  - 遊泳可否・危険情報は「目安」と明示し、現地の遊泳区域表示・ライフセーバー・気象庁の海の警報を優先する固定文言。
  - 気象条件が不可（雷・高波）のときはプランを出さず中止を勧める。
  - 医療的断定（熱中症診断等）はしない。予防行動のみ。
- **出し分け**: 観光客向け（丁寧・持ち物詳しめ） / 地元向け（簡潔） / 事業者向け（客への案内文ドラフト）。

## アーキテクチャ
```
[気象庁 obsdl / bosai forecast・amedas] --+
[気象庁 tide (obs/astro/time)] -----------+--> [スコアエンジン(ルール): 用途別重み + 不可ゲート]
[スポットJSON]                            --+                  |
                                          [72hタイムライン化]
                                                   |
        スコア内訳 + 潮見表 + ユーザー条件 --> [LLM: 半日プラン生成(引用制約)]
                                                   |
                          [Web UI: 地図 + スコア帯グラフ + プラン + 警告]
```
- Web UIは `jma_app_suite` / `tide_viewer` のコンポーネントを流用（Vanilla JS）。地図は軽量タイル。

## MVPスコープ（48h）
- [ ] スポットJSONを5件（恩納村・真栄田・大度浜・トロピカルビーチ・アラハ 等、座標と最寄り観測所）
- [ ] 気象庁から天気・風・降水・日照を取得（過去検証は obsdl、当日は bosai）＋ 波高は公開値の有無を確認
- [ ] 気象庁 bosai tide で該当観測所の潮位・干満時刻取得
- [ ] ルールベースの海日和スコア（snorkel / tidepool / swim の3プロファイル）
- [ ] 72時間タイムラインの帯グラフ
- [ ] LLMで「明日のベストタイム＋半日プラン＋持ち物＋警告」を生成
- [ ] Web1画面: スポット選択 → スコア → プラン

### ストレッチ
- 地図で複数スポット比較、離岸流ハザードの重ね合わせ、評価フィードバック学習、多言語（英・中・韓）、宿泊者向けにチェックイン日から自動提案。

## 3分デモ筋書き
1. （課題）「明日、沖縄で海。何時にどこへ行けば最高?」
2. （操作）スポットを選ぶ → 72時間の帯グラフ。明日の午前がくっきり緑。
3. （内訳）「引き潮10:45、風2m、UV適度、波0.4m」— 数字の根拠が並ぶ。
4. （プラン）「10:30着で磯観察、12時に日陰、13:30から泳ぐ。日焼け止めと…」が即生成。
5. （警告）別の日を選ぶと「うねり2.5m＋雷、遊泳中止を推奨」。
6. （締め）「潮も波も風も日差しも、ぜんぶ読んで"半日"を設計する」。

## リスクと対策
| リスク | 対策 |
|---|---|
| 波高の公開データが薄い / 1年分そろわない | 気象庁の公開波浪情報（沿岸波浪・ナウファス）で入手可否を先に確認。ダメなら「波」項目を外し、天気・風・潮位・UVでスコアを構成 |
| スコア式が恣意的に見える | 内訳を全部見せる、用途別の重みを説明、不可ゲートの理由を明示 |
| 安全情報の誤り（遊泳可否） | 「目安」と免責、現地表示・海の警報・ライフセーバー優先を固定文言、危険時はプランを出さない |
| tide_obsの96点スライス取り違え | tide_viewer の既知の注意点をコードコメントに、テストで端を確認 |
| スポット数が少なく汎用性が弱く見える | JSONを増やすだけで拡張可能と示す、任意地点（座標入力）モードを用意 |

## ID-31（自然言語フロント）との統合
- 「今週末、子連れでシュノーケルできる日ある?」→ 用途=snorkel、週末の各日をスコアリングして回答。
- 「真栄田岬、明日の何時がいい?」→ タイムラインとプランを返す。
- チャットに帯グラフと地図ピンを差し込む。
