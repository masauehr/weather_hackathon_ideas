# ID-32 天気図VLM解説（＋教材モード）

**[← README（目次）](../../README.md)** ・ [候補一覧](README.md) ・ 他候補: [c17 ビーチ日和](c17_beach_day_planner.md) / [c05 気象病](c05_meteoropathy_assistant.md) ・ 参照: [idea_catalog ID-32](../idea_catalog.md) ・ [genai_angles GA-05](../genai_angles.md) ・ [existing_assets](../existing_assets.md)

## 一言
地上天気図・高層天気図・衛星画像をVLMに読ませ、気圧配置を判定して「なぜこの天気か・明日どうなるか」を平文で解説する。あわせて「天気図の読み方」を学べる教材モードを持つ。

## 課題 / 誰のため
- 天気図は情報密度が高いが、読み方を知らないと意味が取れない。予報士の解説は数が限られ、一般には届きにくい。
- ターゲット: 気象に興味のある一般人、防災担当者、理科教育の現場、気象予報士試験の学習者。

## 提供する体験
1. **今日の天気図を解説**: 最新の地上天気図＋500hPa＋ひまわり赤外を取得 → VLMが「西高東低が強まる冬型。等圧線が縦縞で混み、日本海側は雪、太平洋側は乾燥した晴れ。北風が強い」と解説。確信度と「要確認ポイント」を併記。
2. **気圧配置の分類**: 冬型 / 南岸低気圧 / 梅雨前線 / 太平洋高気圧 / 台風 / 移動性高気圧 …のラベルを付け、根拠（前線の位置、低気圧の中心示度、等圧線間隔）を示す。
3. **教材モード**: 天気図上の要素（前線記号、高低気圧、等圧線、閉塞点）を指し示しながら順に説明。「この前線が通過すると気温はどう変わる?」とクイズを出し、回答を採点。
4. **過去との比較**: 「10年前の同じ日の気圧配置」を並べて違いを説明（[ID-33](../idea_catalog.md) と接続）。

## データ（入力）
| データ | 取得元 | 備考 |
|---|---|---|
| 地上天気図（アジア太平洋 ASAS） | 気象庁 天気図ページの画像 | 3時間毎。過去分もアーカイブあり |
| 高層天気図（AUPQ35 / AUPQ78） | 気象庁 | 500/700/850/300hPa |
| ひまわり衛星（赤外・可視・水蒸気） | 気象庁 bosai 衛星タイル or 画像 | 10分毎 |
| アメダス実況（気温・風・降水） | bosai amedas JSON | 解説の裏取り・数値の引用元 |
| 予報（テキスト） | bosai forecast JSON | VLM解説と府県予報の突き合わせ |
| （教材用）天気図の読み方テキスト | 気象庁 知識ページ等をRAG | `RAG_met` 資産 |

## MLパート
- 主役はVLM。追加のMLは軽量:
  - 気圧配置ラベルの**教師あり分類**（任意）: 過去N年の天気図に人手 or ルールでラベル付け、画像特徴量 or VLM出力を入力に小さな分類器。VLM単体の分類が不安定な場合の安定化。
  - 等圧線間隔から**風の強さの目安**を回帰（画像処理＋簡易回帰）はストレッチ。
- ベースライン: 府県天気予報のテキストをそのまま出す（VLM解説がこれを上回るか比較）。

## 生成AIパート
- **入力**: 天気図画像（複数）＋ その時刻のアメダス実況サマリ（JSON）＋ 府県予報テキスト。
- **出力スキーマ（構造化）**:
  ```
  {
    "pattern": "冬型（西高東低）",
    "confidence": 0.82,
    "evidence": ["等圧線が南北走向で本州付近に密集", "大陸に1044hPaの高気圧", "日本の東海上に低気圧"],
    "today": "日本海側は雪や雨、太平洋側は晴れて乾燥。北〜北西の風強い。",
    "tomorrow": "冬型緩み気温上昇、風弱まる見込み。",
    "check_points": ["低気圧の発達度合いで太平洋側の雲量が変わる"],
    "caveats": "画像の読み取りに基づく推定。正式な予報は気象庁発表を参照。"
  }
  ```
- **文章化**: スキーマ → 対象読者別（一般 / 防災 / 子ども / やさしい日本語）にテンプレ生成。
- **ガードレール**:
  - 数値（気温・風速・示度）は必ずアメダス実況 or 予報JSONから引用。VLMに数値を推定させない。
  - `pattern` は許可リスト（分類ラベル集合）から選ばせる。自由記述の病名的断定を禁止。
  - `confidence < 0.6` は「判断が難しい」旨を前面に出す。
  - 教材モードのクイズ採点は、正解データを別途用意しVLMの自己採点に依存しない。
  - 府県予報と食い違う場合は「公式予報と差異あり」と明示。

## アーキテクチャ
```
[画像取得ジョブ] --(天気図/衛星PNG)--> [前処理: リサイズ・トリミング・複数結合]
[bosai JSON取得] --(実況・予報)--------> [コンテキスト整形(JSON)]
                                             |
                       画像 + JSON ---> [VLM: 分類+解説(スキーマ出力)]
                                             |
                          [検証: 数値引用チェック・ラベル検証・予報突合]
                                             |
                     [文章化: 読者別テンプレ] --> [Web UI: 画像 + 解説 + 教材モード]
```
- Web UIは `~/web/webapp/weatherChartGmsViewer`（**2026-09-28発見・実機確認**、`~/projects`外にある個人作成の資産）を土台にする。OpenLayersで地図上に天気図(日本周辺/アジア域)・ひまわり衛星(赤外/可視/水蒸気)・降水レーダーを重ね合わせ、ズーム・海岸線・緯度経度グリッド・解析日時選択も備えた本格ビューア。取得元URLは`fetch_chart.py`と同じbosai系で、CORS回避のPHPプロキシ（`cgi/get_contents.php`）も同梱（社内ネットワーク向けの分岐があるが自宅環境では素通しで動く）。
  - なお`jma_app_suite`（`~/projects`内）には天気図の表示アプリ自体は無い（予報/レーダー/衛星のタイルアニメーション系のみ、2026-09-28実機確認）。
- 教材モードの解説文は `RAG_met`（**2026-09-28実機確認: `RAGQuery.ask()`で動作、総観気象学教科書・気象庁予報用語集から出典ページ付きで回答を取得済み**、例:「前線とは何か」→総観気象学p.168等）をそのまま使える。
- VLMは Claude（画像対応）。ローカルVLMは品質未知なので本命はクラウド。

## 3分デモ筋書き（2026-09-28、実測データに基づき更新）

前提: スパイクで**正答率67%（15事例）**、「日本海低気圧⇄南岸低気圧」を系統的に混同する弱点も判明済み（[experiments/cs32_chart_vlm/README.md](../../experiments/cs32_chart_vlm/README.md)）。**当たる時だけを見せる構成にはしない**（外れた時に会場で実演してしまうと逆効果）。「間違えることもあるが、ガードレールで検知できる」を差別化ポイントとして正面から見せる。

| 時間 | 内容 | 話す内容・実際の材料 |
|---|---|---|
| 0:00–0:20 | **課題** | 生の天気図（前線記号・等圧線・示度が密な画像）を見せ「これ、読めますか？」。会場のほとんどが読めない前提で進める |
| 0:20–0:50 | **入力→出力** | 今日の天気図＋衛星画像をアプリに投入 →3秒程度でVLMが解説。**実測例**（2026-09-25）: 「移動性高気圧に緩やかに覆われ、風は弱く雨の心配は小さい」。根拠3点（示度1020/1016hPa、等圧線の間隔、台風の位置）をハイライト |
| 0:50–1:30 | **信頼性を見せる（最大の差別化ポイント）** | 「このAIは外すこともある」を隠さず言う。確信度0.65のバッジ、ガードレールが「数値は実況からしか引用しない」「季節外れのラベルは自動で弾く」を実演。**「15種類の天気パターンで試したら正答率67%。台風や梅雨前線はほぼ当たるが、低気圧の細かい型は苦手」と数字で言う**。予報士でも難しい仕事をAIが試みて、しかも自分の限界を自己申告できる、という誠実さで信頼を作る |
| 1:30–2:00 | **読者切替** | ボタンひとつで小学生向け解説に変わる |
| 2:00–2:40 | **教材モード** | 「等圧線の間隔が狭い＝風が強い」をクイズで体験。正解して盛り上がる |
| 2:40–3:00 | **締め** | 「予報を"読む力"を、誰でも持てるように。ただし過信させない」 |

**デモ運用の注意**:
- ライブでは**必ず事前に結果を1回確認したケース**を使う（本番中に外れると弱い）。台風・梅雨前線・移動性高気圧の事例は実測で強い（3/3, 1/2, 2/2）ので、その中から選ぶ。
- 予備として、あえて「外れた事例」も1つ持っておき、質疑応答で「じゃあ外れたらどうなるんですか」と聞かれたら即座に見せられるようにする（正直さのアピールになる）。

## リスクと対策
| リスク | 対策 | 実測での裏付け |
|---|---|---|
| VLMが前線位置や示度を誤読し、もっともらしい嘘を言う | 数値は必ず実況JSONから引用／ラベルは許可リスト／予報と突合して差異を明示／confidence表示 | 実装済み・自己テスト3/3。実際に「6月のデータを秋雨前線と誤答」を季節整合ルールで機械的に弾けることを確認 |
| **気圧配置の分類精度そのものが低い場合がある** | confidence表示で「判断が難しい」を前面に出す。「日本海低気圧⇄南岸低気圧」等、弱いパターンは事前に把握しデモで避ける | **15事例で正答率67%を実測**。台風・梅雨前線・移動性高気圧は強い、低気圧の地域型は系統的に混同 |
| 教材の説明が不正確 | RAGで気象庁の記述を根拠に、出典リンクを併記。クイズ正解は人手で用意 | 未検証（教材モードは未着手） |
| 「解説が府県予報と同じで新規性が薄い」と見られる | 読者別出し分け・教材モード・過去比較で差別化。予報にない"なぜ"を語る／**「自分の弱点を自己申告するAI」という誠実さも新規性として押す** | — |
| 画像取得が不安定（サイト構造変更） | 取得済みサンプルを同梱してデモは確実に動くように | 実装済み（`fetch_chart.py`は認証不要のbosai JSON/PNG/タイルのみ使用） |
