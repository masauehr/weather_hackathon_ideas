ハッカソンで実際に作る 1〜3 案に絞るための評価。**要項が出たら審査基準に合わせて重みを更新すること。**

## 評価軸（各 1〜5 点）

| 軸 | 説明 |
|---|---|
| D 入手性 | 開発時間内にデータが揃うか（Open-Meteoだけで済む=5、要申請・手集め=2） |
| N 生成AI必然性 | LLM/VLMが無いと体験が成立しないか（[genai_angles.md](genai_angles.md)） |
| R 既存流用 | ~/projects の資産をどれだけ使えるか（[existing_assets.md](existing_assets.md)） |
| F 実現可能性 | 48h級でMVPが動くか（GPU不要・スコープ明快=高） |
| W デモ映え | 審査でひと目で伝わるか（地図・チャット・ビフォーアフター） |
| I インパクト/新規性 | 課題の切実さ・目新しさ |

暫定スコア = D + N + R + F + W + I（30点満点）。要項判明後に重み付き平均へ。

## 現時点の第一次候補（要項前）

1. **ID-32 天気図VLM解説**（＋教材モード）— AI必然性・デモ映え・拡張性が高い
2. **ID-17 ビーチ日和＋観光プラン**（＋ID-31 の対話フロント）— 既存資産と地域性
3. **ID-05 気象病アシスタント** — データが軽く共感性が高い、個別化でAI必然

いずれも **ID-31 の自然言語フロント** を共通土台にできる点で相性が良い。

## 絞り込みプロセス
1. 要項（テーマ・審査基準・利用可能API・時間）を [plan.md](plan.md) に転記
