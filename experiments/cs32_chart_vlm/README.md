## VLM とは
**VLM（Vision-Language Model、視覚言語モデル）** は、画像とテキストの両方を入力に受け取り、テキストで答えるAIモデル。

| | 入力 | 出力 |
|---|---|---|
| LLM | テキストのみ | テキスト |
| VLM | 画像 ＋ テキスト | テキスト |

- 写真・グラフ・スクリーンショット・天気図などを見て「何が写っているか」「何が読み取れるか」を言葉で答える。Claude は画像対応のため VLM として使える。
- **本アイデア（ID-32）での役割**: 天気図・衛星画像とアメダス実況（テキスト）を一緒に渡し、①高気圧・低気圧・前線・台風の位置と気圧配置の型の判定、②「なぜこの天気か・明日どうなるか」の平文解説、を出させる。天気図は等圧線・前線記号・示度が密に描かれた画像で、従来は専用の画像処理が必要だった。VLM なら画像を渡すだけで読める点が「生成AIの必然性」。
- **注意**: 画像の細部（示度の数字、前線の位置など）を**もっともらしく読み違える**ことがある。そのため本スパイクでは、ラベルの許可リスト・季節整合・数値引用チェック・実況突合・予報突合のガードレールで出力を検証している（→ [validate.py](validate.py)）。
- 本スパイクでは API キー未設定のため、Claude Code セッション自身を VLM 役として使った（詳細は「限界」参照）。

| ファイル | 役割 |
|---|---|
| [fetch_chart.py](fetch_chart.py) | 地上天気図（アジア/日本近海）・ひまわり赤外(B13)・アメダス主要8地点・府県予報概況を取得。日本近海天気図の対象時刻に衛星・アメダスを揃える |

| [fetch_hibiten.py](fetch_hibiten.py) | 気象庁「日々の天気図」（月次PDF、2002年8月〜）から指定日の天気図だけを機械的に切り出す。正解ラベル（見出し）付きの過去事例を作る |
| [eval_historical.py](eval_historical.py) | 複数の過去事例（天気図のみ、実況・予報なし）でVLMに気圧配置を判定させ、見出しベースの正解ラベルと突き合わせて正答率を出す |

- 当日1事例: `python fetch_chart.py` → `python vlm_read.py data/<対象時刻UTC>` → `python validate.py data/<対象時刻UTC>/vlm_output_api.json data/<対象時刻UTC>`
- 過去事例で正答率測定: `python fetch_hibiten.py <year> <month> [day]` → `python eval_historical.py`
（`data/` は git 除外）

## 複数事例での正答率検証（2026-09-28）
天気図単体（実況・予報なし）で気圧配置を当てられるかを、7パターン×15事例で測定。正解ラベルは気象庁「日々の天気図」の見出し（予報官が書いた要約）から、[validate.py](validate.py) の許可リストに一致するものだけを機械的に採用（曖昧な見出しは除外）。

**分かったこと**:
- **台風・梅雨前線・移動性高気圧は強い**（台風3/3、梅雨前線1/2、移動性高気圧2/2）。特徴的な渦・停滞前線・高気圧の縁取りが読み取りやすいためと考えられる。
- **「日本海低気圧」を2/2とも「南岸低気圧」に誤答**（系統的な混同）。低気圧の存在自体は検出できているが、日本海側か南岸側かという**地域の判定を間違えやすい**。
- **6月のデータを「秋雨前線」と誤答**（確信度0.75の高確信度エラー）。[validate.py](validate.py) の季節整合ルール（秋雨前線は9〜11月のみ許可）に通せば、この誤答は機械的に弾ける — **単発の確信度チェックだけでなく季節整合ガードレールが実際に効く**具体例。
- **確信度は弱いが手がかりになる**: 正答時の平均確信度 0.72、誤答時 0.61。ただし正答でも0.6のケース、誤答でも0.75のケースがあり、確信度だけでは判別しきれない。
- サンプルが少ない（各パターン1〜4事例）ため、正答率67%は粗い推定値。特に「日本海低気圧」は2/2とも同じ誤り方をしており、系統的な弱点の可能性が高い。

## 発見・注意
- **実況の時刻ずれ**: 最初は最新アメダス（15時JST）と天気図（12時JST）を混ぜていた。時刻合わせが必須で、`fetch_chart.py` は天気図の対象時刻を基準に統一済み。
- **許可リストだけでは足りない**: ラベルの形式チェックと「中身の妥当性」は別。季節整合のような外部知識ルールが要る。
- 設計書の「数値は実況JSONから引用」は、**天気図上の示度（hPa）には適用できない**（アメダスに無い値）。示度は `chart_values` に分離し、要目視確認 or 別途 OCR/突合が必要。

## 限界（過大評価しないために）
1. **当日1事例（実況・予報つき）は「秋の穏やかな日」で難易度は低い**。多数事例検証（15件）は天気図単体（実況・予報なし）なので、両者を単純に足し合わせて評価できない。
2. **正解ラベルが「気象庁の見出し」由来**。予報官の一言要約であり、気象学的に唯一の正解ではない（例: 複数パターンが同時に存在する日をどちらか一方に丸めている）。
3. **サンプル数が少ない**（1パターンあたり1〜4事例）。67%という数字の信頼区間は広い。
4. **天気図単体のみ**（衛星・実況・予報なし）。当日スパイクで使った実況突合・予報突合のガードレールは、過去事例では使えない（bosaiに過去実況アーカイブがないため）。
5. `validate.py` の数値引用チェックは文字列の部分一致で甘い（短い数字は誤って通りうる）。突合の合成テストも自作で、実 VLM の誤りの型を網羅していない。
6. 赤外画像の雲の解釈（帯状雲＝前線等）は目視のみで、定量評価していない。
