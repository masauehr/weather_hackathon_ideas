# ID-37 スパイク: バス遅延は天気で説明できるか — 都営バス×アメダス

**[← experiments/](../README.md)** ・ 元アイデア: [ID-01派生](../../docs/idea_catalog.md)の発展（交通×気象の別アプローチ）

ODPT（公共交通オープンデータ）のリアルタイム位置情報と時刻表を突き合わせて東京都交通局（都営バス）
の遅延を算出し、最寄りアメダス観測点の降水量と突き合わせて、天気とバス遅延の関係を検証中。
ODPTには履歴アーカイブが無いため、launchdで5分おきに定期ポーリングして自分でログを蓄積している。

収集状況は [モニターページ](https://masauehr.github.io/weather_hackathon_ideas/)（約30分おきに自動更新）で確認できる。

## 状態（途中経過）

- **2026-10-02 データ収集開始**。ODPTの`odpt:Bus`（リアルタイム位置情報）と`odpt:BusTimetable`
  （時刻表）を突き合わせて遅延（秒）を算出するパイプラインを構築（[src/poll_bus_delay.py](src/poll_bus_delay.py)）。
  バス停に最も近いアメダス観測点の10分降水量を同じ行に付与。
- **2026-10-06時点で約14万件を蓄積**（2026-10-02 08:56〜）。launchdは5分おきの設定だが、
  Macがスリープしている間は実行されないため、実際のポーリング間隔は不規則（数十分〜1時間超の
  空白が生じることがある）。「PCがネットに繋がっている時間しかデータが取れない」という制約を
  受け入れて運用中。
- **降水と遅延の関係を初めて確認（2026-10-06）**: この時点で記録された降水イベントは2回のみ
  （2026-10-02午前・2026-10-05午前、いずれも10分降水量0.5〜1.0mm＝1時間換算3〜6mm程度の弱い雨）。
  降水あり（n=2,204）の平均遅延156.5秒 vs 降水なし（n=133,063）の平均遅延155.1秒、
  Cohen's d=0.007・相関r=0.001と、**現時点では降水と遅延に関係は見られない**。
  まだ降水イベントが2回だけで、かつ弱い雨に限られているため、サンプルとして判断するには早すぎる。
  強い雨のイベントが観測された時点、あるいは十分な件数が蓄積された時点で再確認する。
- **時間帯（通勤ラッシュ）と遅延の関係を確認（2026-10-06）**: 平日データを時刻別に集計したところ、
  夕方〜夜（16〜22時台）はほぼ単日データしかなく、7時・18〜20時台は完全に欠落していた
  （launchdがMacのスリープ中は動かず、ポーリング間隔が不規則なため）。複数日（3日分）のデータが
  揃っている午前〜昼（8〜14時台）だけで見ると、平均遅延は8時148.6秒・9時132.1秒・12時150.4秒・
  14時125.8秒で、朝ラッシュより正午前後がむしろ遅い結果となり、直感的な「朝夕ラッシュで遅れる」
  という仮説は今のところ支持されない。ただし3日分のみのため、**通勤時間帯の効果は確認も否定もできる
  段階ではない**。夕方帯は複数日のデータが揃うまで評価自体ができないため、まずはデータ蓄積を継続する。

- **予備解析（2026-11-05, 約109万イベント・35日）**: [src/analyze_prelim.py](src/analyze_prelim.py)、結果は
  `results/prelim/`（regression.csv・daily_within_effect.csv・prelim.png）。
  - 設計: (bus_id,busstop,予定時刻)で重複除去、遅延は0.5〜99.5%でウィンザー化、
    路線＋日付＋曜日×時間帯の固定効果を吸収、日付クラスタ頑健SE。降水は10分降水量（0.5mm刻み）。
  - 結果（路線+日付+曜日×時間帯FE、降水あり vs なし）: **平均遅延 +25秒（全日、t=3.3）／+30秒（平日、t=3.8）**、
    **5分超遅延の確率 +3.5pp（全日）／+4.2pp（平日）**。1.0mm以上では +42〜48秒と大きいが
    n=4,556で有意ではない（t=1.7〜2.0）。雨の日を1日ずつ除くジャックナイフでも +17〜29秒で符号は不変。
  - 注意点（結論を弱める材料）:
    1. **固定効果なし／路線+時間帯のみでは有意でない**（t≈1.1〜1.8）。日ごとの混雑差が雑音になっている。
    2. **同日・同路線・同時間帯の単純対比では平均 +3秒**（8日中5日が正、10/26の最大降水日は −9秒）で、
       回帰の +25秒より大幅に小さい。推定が設計に敏感。
    3. 降水イベント日は**8日のみ**、1mm以上は4,556件。日付クラスタ数は35だが、効果を担うのは実質8日で、SEは楽観的。
    4. 弱い雨（10分降水0.5mm＝1時間換算3mm程度）が大半で、強雨の効果は未検証。
  - 結論: **「弱い雨で遅延がやや増える傾向（+20秒前後、5分超確率+3〜4pp）」止まり。強雨・因果は未確認。**
    デモで主張するなら「傾向が見える」程度に留め、断定は避ける。

## 今後

- 強雨（10分降水1mm以上）と降水日が増えるまで収集を継続し、同じスクリプトで再推定する。
- 降水の遅れ効果（直近1時間の累積降水）、路線・バス停単位の異質性を検討する。

- 継続してデータを蓄積し、降水強度別（弱い雨/強い雨）での遅延への影響を再検証する。
- 時間帯（通勤時間帯か否か）・路線・バス停など他の要因との交絡も考慮する必要がある。
- 十分なデータが溜まった段階で、ID-01（九州の出力制御）と同様にロジスティック回帰等での検証に進む。
